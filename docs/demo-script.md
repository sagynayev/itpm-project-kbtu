# Demo script — 4 минуты

## 0:00–0:35 — проблема

«Текст ПДД точный, но в реальной ситуации нужный пункт сложно быстро найти. Обычный chatbot отвечает быстрее, но его ответ нельзя принимать на веру. PDD Check соединяет удобный вопрос с проверяемым источником».

## 0:35–1:05 — landing

- показать главное обещание;
- проговорить правило «без источника — без ответа»;
- открыть блок надёжности и указать ИПС «Әділет».

## 1:05–2:20 — основной flow

1. Зарегистрироваться.
2. Задать вопрос: «Нужно ли уступать пешеходу на нерегулируемом переходе?»
3. Показать короткий ответ, retrieval score и статус guardrail.
4. Раскрыть официальный пункт.
5. Открыть ссылку на «Әділет».

## 2:20–2:55 — негативный сценарий

Задать нерелевантный вопрос. Показать `Источник не найден`, объяснить, почему отсутствие ответа безопаснее выдумки.

## 2:55–3:30 — продукт

- история сохраняется;
- профиль хранит уровень и дату экзамена;
- база обновляется воспроизводимым импортом;
- feedback создаёт данные для оценки качества.

## 3:30–4:00 — завершение

«MVP доказывает основной flow: спросить → найти → проверить. Следующий измеримый шаг — 100 размеченных вопросов, recall guardrail ≥ 0.90 и usability test на пяти пользователях».
